应用层

发表于 2026-05-14

一、应用层通信模型

应用协议定义终端设备间的应用通信规则；通信模型体现应用协议宏观通信规则，主要分为两类：

  1. C/S（客户端-服务器）模型
  2. P2P（点对点）模型

P2P模型特点

  • 设备无明显角色特征
  • 设备之间建立对等连接，实现对等通信
  • 设备既可提供服务，也可请求服务

二、基于TCP协议的远程访问应用层协议

1. Telnet协议

  • 通信模型：C/S
  • 传输层协议：TCP
  • 端口号：23
  • 数据形式：明文
  • 角色定义：客户端为管理设备，服务器为被管理设备

2. SSH协议（Telnet改进版）

  • 提供服务器认证，客户端可识别服务器身份
  • 用户认证支持密码认证、公钥认证两种方式
  • 用户认证信息以密文传输或不传输
  • 用户业务数据全程密文传输

三、基于UDP的应用层协议

DHCP协议

  • 作用：为特定网络内设备分配IP地址、DNS等信息
  • 通信模型：C/S
  • 传输层协议：UDP
  • 端口号：67、68
  • 数据形式：明文

四、同时基于TCP和UDP的应用层协议

DNS协议

1. 核心作用

实现计算机名称与IP地址双向解析。

2. 基础参数

  • 通信模型：C/S
  • 传输层协议：TCP/UDP
  • 端口号：53
  • 数据形式：明文

3. 域名产生原因

网络计算机可通过IP地址唯一标识，但IP地址不易记忆，且无法永久绑定设备；域名由点分隔字符组成，可建立域名与IP地址映射关系，访问域名等同于访问IP地址。

4. 早期非等级域名空间缺陷

  • 字符域名易产生命名冲突
  • 域名空间集中管理，设备增多加重管理负担
  • 域名与IP映射常变动，维护工作量大

5. 域名层级划分

顶级域分组织模式、地理模式：

模式 示例 说明
组织模式 com、edu、gov、mil、net、int、org 商业组织、教育机构、政府机构等
地理模式 cn（中国）、us（美国） 按国家划分

6. 域名解析查询方式

  • 递归查询：本地DNS服务器无记录时，由该服务器代为查询其他DNS服务器，直至获取结果返回客户端。
  • 迭代查询：本地DNS服务器无记录，仅告知客户端下一级服务器地址，由客户端自行继续查询。

7. 域名解析分类

  • 静态域名解析：手动配置域名与IP映射表，如Windows系统hosts文件。
  • 动态域名解析：通过域名解析器，依靠DNS客户端与服务器报文交互完成解析。

8. DNS完整查询流程

DNS客户端 → 本地域名服务器 → 根域名服务器 → .com顶级域名服务器 → huawei.com域名服务器 → 返回对应IP地址

五、Web应用相关协议

1. 万维网（WWW）

由大量相互链接的超文本组成的系统，需解决三大问题：

问题 解决方案
超文本页面编辑排版 HTML 规范页面表现形式
页面位置标识 URL 唯一标识网络资源
页面信息传输 HTTP 规范数据传输流程

2. HTML超文本标记语言

  • 用途：编写超文本文档的结构语言
  • 组成：头部（Head）、主体（Body）两大核心部分

3. URL统一资源定位符

  • 俗称网址，用于定位网络资源，支持存取、更新、查找资源属性等操作
  • 标准格式：<协议>://<主机>:<端口>/<路径>

4. HTTP协议

  • 全称：超文本传输协议
  • 作用：实现WWW客户端与服务器间信息传输
  • 通信模型：C/S
  • 传输层：TCP
  • 端口号：80
  • 数据形式：明文

5. HTTPS协议

  • 全称：安全超文本传输协议
  • 通信模型：C/S
  • 传输层：TCP
  • 端口号：443
  • 数据形式：密文
  • 发展历程：HTTP无安全机制 → 1994年网景推出SSL → 1996年IETF标准化为TLS → HTTPS又称HTTP over SSL/TLS
  • SSL位置：部署在TCP/IP模型传输层与应用层之间
  • SSL协议框架：SSL握手协议、SSL密码变化协议、SSL警告协议、SSL记录协议

6. HTTP版本差异

版本 特点
HTTP 1.0 每个请求对象都需新建、断开TCP连接，请求多时效率极低
HTTP 1.1 建立一次TCP连接后，可复用连接收发多个请求响应消息，提升传输效率

六、电子邮件应用协议

1. 邮件架构演变

  • 早期：发送方与接收方一对一通信
  • 现在：用户代理 → 邮件服务器 → 互联网中转传输

2. 邮件服务器特性

遵循C/S模型，同一台服务器可同时充当客户端与服务器，具备收发邮件双重能力。

3. 主流邮件协议

  • 发送邮件：SMTP、ESMTP
  • 接收邮件：POP3、IMAP

SMTP协议

  • 不足：无身份认证、明文传输数据
  • ESMTP改进：新增扩展选项，支持TLS安全加密传输

POP3协议

  • 作用：用户代理从邮件服务器下载邮件
  • 通信模型：C/S
  • 传输层：TCP
  • 端口号：110
  • 数据形式：明文

IMAP与POP3区别

  • POP3：客户端可下载服务器邮件，但客户端删除、标记已读等操作不同步到服务器。
  • IMAP：支持网页邮箱与客户端双向通信，客户端所有操作实时同步至服务器。
