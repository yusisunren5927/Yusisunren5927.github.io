一、基础概述

  1. PPP、HDLC 都是广域网链路层点到点协议，用于串行串口链路封装。
  2. 华为设备串行接口默认封装协议是 PPP。
  3. 串口为点到点类型，不需要 MAC 地址、不需要 ARP。
  4. 链路两端封装协议必须一致才能正常通信。

二、HDLC 协议

1. 简介

HDLC：高级数据链路控制，面向比特的链路层协议。

2. 对比 PPP

特性 HDLC PPP
认证功能 不支持 支持 PAP/CHAP 认证
差错检测 无 有
差错恢复 无 有
同步/异步链路 仅同步 同步、异步都支持

三、PPP 协议整体架构

PPP 由两部分核心组件组成：

  1. LCP 链路控制协议
    • 负责建立、维护、拆除 PPP 链路
    • PAP/CHAP 认证在 LCP 阶段完成
  2. NCP 网络层控制协议
    • 为不同网络层协议协商参数
    • 常用 IPCP 用于协商 IPv4 参数
    • 串口没配IP时，IPCP 状态为 Closed

四、PPP 两种认证方式 PAP / CHAP

1. PAP 密码认证协议

  • 明文传输用户名和密码，安全性低，易被抓包暴力破解
  • 二次握手：被认证方主动发账号密码 → 认证方返回同意/拒绝
  • 仅链路建立阶段认证一次，后续不再校验

2. CHAP 挑战握手认证协议

  • 不传输明文密码，用 MD5 哈希加密
  • 三次握手：认证方先发随机挑战报文 → 被认证方加密响应 → 认证方比对结果
  • 防暴力破解，链路建立后还会定期重认证
  • 企业远程接入、VPN 场景常用

NAT 网络地址转换 完整版知识点总结

一、NAT 基础概念

  1. 全称：Network Address Translation 网络地址转换
  2. 产生背景：解决 IPv4 公网地址枯竭 问题，作为 IPv6 普及前过渡技术。
  3. 核心作用：私网地址 ↔ 公网地址 转换
    • 私网地址不能在公网路由，必须经过 NAT 转换才能上网
    • 多台内网主机可共用一个公网IP，节省公网地址
  4. 部署位置：内网和外网之间的网关路由器/三层交换机

公网地址 & 私网地址区别

  • 公网地址：ISP 分配、全球唯一、可直接上互联网、需要付费
  • 私网地址：企业/家庭内网自用、免费、可重复使用、不能公网路由
  • NAT 就是实现：私网访问公网必须转换成公网地址

二、NAT 四大核心类型

1. 静态 NAT

  • 一对一固定映射：一个私网IP永久绑定一个公网IP
  • 特点：
    • 固定不变，适合外网主动访问内网服务器
    • 无法节省公网地址，一对一占用
  • 应用场景：内网服务器对外提供服务
  • 配置命令：

2. 动态 NAT

  • 基于公网地址池，私网用户上网随机分配地址池里的公网IP
  • 特点：
    • 用完释放，循环复用
    • 地址池耗尽时，新主机无法上网
  • 可加参数 no-pat：只换IP、不转换端口

3. NAPT 端口地址转换（PAT）

  • 多对一：多个私网IP共用同一个公网IP，靠不同端口区分
  • 原理：IP相同、端口不同，实现多主机同时上网
  • 企业、家庭最常用，极大节省公网地址

4. Easy IP

  • 属于 NAPT 的简化版
  • 直接借用外网物理接口自身的公网IP，不用创建地址池
  • 适用：家庭、小型办公、拨号动态获取公网IP场景
  • 配置：接口下直接绑定 ACL 即可

三、NAT Server 服务器映射（端口映射）

  1. 作用：让外网主动访问内网服务器
  2. 原理：把「公网IP+端口」映射到「私网服务器IP+端口」
  3. 也叫端口映射
  4. 配置命令：
  1. 特点：外网只能看到公网地址，隐藏内网真实私网地址，起到安全屏蔽作用

四、各类 NAT 对比

  1. 静态NAT：一对一、固定映射、适合服务器发布
  2. 动态NAT：地址池随机分配、无端口转换、地址池满就断网
  3. NAPT：多对一、端口区分、最省公网地址
  4. Easy IP：借用接口IP、无需地址池、适合小型网络
  5. NAT Server：端口映射，外网访问内网专用

五、常用配置命令

  1. 查看静态NAT：display nat static
  2. 查看地址池：display nat address-group
  3. 查看出站NAT：display nat outbound
  4. 查看NAT服务器映射：display nat server

六、核心原理与必记考点

  1. 没有 NAT：内网可以主动发往外网，但外网无法回包，路由找不到内网主机
  2. NAT 天然隐藏内网拓扑和私网地址，有基础安全防护
  3. 动态NAT：地址池地址用完，新主机只能等释放后才能上网
  4. NAPT vs Easy IP
    • NAPT：需要配置公网地址池
    • Easy IP：不用地址池，直接用外网接口IP
  5. 所有源NAT都在外网出接口配置
  6. 静态NAT、NAT Server 支持外网主动访问内网；普通NAPT/Easy IP 默认外网无法主动访问内网

acl

发表于 2026-05-15

一、ACL 基础概念

ACL 全称：Access Control List 访问控制列表

  1. 作用：定义规则对数据包分类、允许/拒绝流量通过
  2. 用途：控制网络访问、限制流量、提升网络性能、防御网络攻击
  3. 定位：属于包过滤基础防火墙技术，是早期第一代防火墙机制
  4. 原理：由多条规则组成，按顺序逐条匹配，匹配即执行动作

二、ACL 工作机制

  1. 每条规则包含：编号、时间段、匹配条件、执行动作
  2. 动作只有两种：permit 允许、deny 拒绝
  3. 规则编号：默认步长 5（5、10、15…），方便中间插入规则
  4. 匹配顺序：从上到下依次匹配，匹配到就立即执行，不再往下匹配
  5. 所有规则都不匹配 → 默认拒绝丢弃

三、ACL 三大类型及编号范围

类型 编号区间 匹配内容 特点
基本ACL 2000–2999 仅源IP地址 只看从哪里来，所有协议都管控
高级ACL 3000–3999 源IP、目的IP、协议、源端口、目的端口 看从哪来、到哪去、什么业务
二层ACL 4000–4999 源MAC、目的MAC、帧类型 基于二层帧过滤

补充：ACL 还分数字型ACL、命名型ACL两种格式。

四、反掩码 / 通配符 核心区别

  1. 子网掩码：连续1和0，1=网络位、0=主机位
  2. 路由反掩码：连续0和1
  3. ACL通配符：可以任意0、1组合
    • 0 必须严格匹配
    • 1 忽略不匹配

常用示例：

  • 192.168.0.1 0.0.0.0 精确匹配单台主机
  • 192.168.0.0 0.0.0.255 匹配整个网段
  • any 等价 255.255.255.255 匹配所有地址
  • 可精准匹配奇数/偶数网段地址

五、基础配置命令

1. 基本 ACL 配置

2. 高级 ACL 配置

可精准控制：源IP+目的IP+协议+目的端口

3. 接口调用 ACL

4. 查看与验证

六、ACL 匹配逻辑重点

  1. 规则按序号从小到大依次匹配
  2. 一旦匹配成功，立刻执行 permit/deny，不再继续匹配
  3. 所有规则都不匹配 → 默认丢弃
  4. 基本ACL只能匹配源地址，不区分协议和端口
  5. 高级ACL可精细管控：源、目的、协议、端口、应用

七、ACL 应用价值

  • 限制非法主机上网，防止内网冲突
  • 禁止特定网段访问服务器（如禁止访问FTP、HTTP）
  • 减少无效流量，节省带宽消耗
  • 基础安全防护，隔离恶意访问流量

dhcp

发表于 2026-05-15

一、DHCP 基础概述

  1. 全称：Dynamic Host Configure Protocol 动态主机配置协议
  2. 由 BOOTP 协议发展而来，应用层协议，基于 UDP 封装
  3. 端口号：
    • 客户端：68
    • 服务器：67
  4. 作用：自动给终端分配 IP、子网掩码、网关、DNS 等参数
  5. 分配的IP带有租期，不是永久使用
  6. DHCP 客户端请求默认以广播发送

二、DHCP 网络组成角色

  1. DHCP Client 客户端：电脑、手机等需要自动获取IP的终端
  2. DHCP Server 服务器：负责分配IP地址池、下发网络参数
  3. DHCP Relay 中继
    • 路由器、三层交换机充当
    • 作用：跨广播域转发DHCP广播报文，让不同网段也能共用一台DHCP服务器
  4. 客户端与服务器不在同一广播域，必须配置DHCP中继

三、DHCP 六种报文类型

报文 作用
DHCP Discover 客户端广播寻找DHCP服务器
DHCP Offer 服务器回应，携带可用IP和网络参数
DHCP Request 客户端广播确认选用哪个服务器的IP、申请租约/续期
DHCP ACK 服务器确认分配IP、下发完整参数
DHCP NAK 服务器拒绝分配IP
DHCP Release 客户端主动释放IP地址

四、DHCP 经典工作流程（四步握手）

Discover（广播）→ Offer → Request（广播）→ ACK

  • 第1、3步固定广播
  • 第2、4步可单播也可广播（教材两种说法都成立）
  • 网络中多台DHCP服务器时，谁先回复Offer，客户端就选用谁的IP

五、DHCP 租期机制

1. 租期更新（50%）

租约用到 50% 时，客户端单播向服务器发起续期请求，成功则刷新租期。

2. 重绑定（87.5%）

50%续期无响应，到 87.5% 时改为广播重新申请IP；
收到ACK继续用，收到NAK立即停用IP。

3. 地址释放

  • 租期到期无续约，自动停用IP
  • 也可手动发 DHCP Release 主动释放

4. APIPA 自动私有地址

Windows 客户端获取不到DHCP地址时，自动给自己分配：
169.254.0.0/16 网段地址，只能同网段临时互通。

5. 租期设置建议

  • 短租期：机场、商场、酒店等流动用户多的场景，增加设备负担
  • 长租期：家庭、企业固定终端，减轻网络负担

六、DHCP 两种地址池

  1. 接口地址池
    • 绑定在三层接口
    • 直接以接口IP作为用户网关
    • 优先级高于全局地址池
  2. 全局地址池
    • 全局创建IP地址池，可被多个接口调用
    • 需手动配置网段、网关、DNS、租期等

七、DHCP 核心配置命令

租期特殊配置

  • lease day 0 hour 0 minute 0 永不超时
  • 等价简写：lease unlimited

九、重点易错知识点

  1. DHCP 基于 UDP 67/68，应用层协议
  2. 跨网段必须 DHCP中继
  3. 接口地址池优先级 > 全局地址池
  4. 地址池 network 网段是必配，网关、DNS为选配
  5. 可配置排除IP，预留给服务器、网关等固定设备

stp技术

发表于 2026-05-15

一、STP 基础概念

  1. 适用场景：只有二层交换机需要STP，三层设备不用。
  2. 为网络做冗余备份链路，但多条链路会产生二层环路。
  3. 环路带来三大危害：
    • 广播风暴无限循环
    • MAC地址表频繁震荡
    • 占用设备CPU、带宽，全网卡顿
  4. STP 默认交换机出厂自动开启；关闭命令：stp disable
  5. STP 属于组播协议，不是广播；组播MAC：01-80-C2-00-00-00

二、STP 两大核心作用

  1. 消除环路：逻辑阻塞冗余端口，把环路修剪成树型无环拓扑
  2. 链路备份：主链路故障，自动放开阻塞端口，恢复通信

三、STP 工作四步流程

  1. 全网选举 根桥
  2. 所有非根桥选举 根端口 RP
  3. 每个网段选举 指定端口 DP
  4. 既不是RP也不是DP的端口，阻塞丢弃

根交换机上没有根端口，所有端口都是指定端口

四、BPDU 桥协议数据单元

  1. STP 靠发送 BPDU 报文进行选举、收敛、维护拓扑
  2. 两种 BPDU：
    • 配置BPDU：选举根桥、端口角色、维持拓扑，根桥每2秒发一次
    • TCN 拓扑变更BPDU：链路故障时向上通知根桥，触发全网MAC表刷新
  3. BPDU 关键字段：
    根桥ID、根路径开销RPC、桥ID、端口ID、计时器

五、核心标识：BID 桥ID & PID 端口ID

1. BID 桥ID（整台交换机标识）

  • 组成：2字节优先级 + 6字节MAC地址
  • 优先级范围：0～65535，默认32768
  • 规则：只能是 4096的倍数
  • 选举：越小越优先 → 先比优先级，相同再比MAC

2. PID 端口ID

  • 组成：高8位端口优先级 + 低8位端口编号
  • 端口优先级默认128，范围0～255

六、路径开销 Path Cost

  1. 带宽越高，路径开销越小，越优先
  2. 根路径开销RPC：到达根桥沿途所有入端口开销累加
  3. 选路原则：开销越低越优先

七、三大角色选举规则

1. 根桥选举

所有交换机初始都认为自己是根桥，比较 BID，最小者成为根桥。

2. 根端口 RP（非根桥上唯一最优端口）

依次比较：

  1. 根路径开销 RPC 最小
  2. 对端 BID 最小
  3. 对端 PID 最小
  4. 本端 PID 最小

3. 指定端口 DP（每个网段选一个）

为每个网段选出唯一转发端口，负责转发该网段BPDU和数据；
规则同样：RPC → BID → PID；根桥所有端口都是DP。

4. 阻塞端口

既不是RP也不是DP，直接被阻塞，不转发用户数据，只监听BPDU。

查看命令：display stp brief

八、STP 端口状态（802.1D）

状态 收BPDU 发数据 学习MAC
Disabled × × ×
Blocking √ × ×
Listening √ × ×
Learning √ × √
Forwarding √ √ √
  • 稳定状态：Blocking、Forwarding
  • 过渡状态：Listening、Learning

与 RSTP 对应

STP 五种状态 → RSTP 简化为三种：
Discarding、Learning、Forwarding

九、STP 三大计时器

  1. Hello Time：2秒，根桥发送BPDU周期
  2. Forward Delay：15秒，监听、学习状态停留时间
  3. Max Age：20秒，超时收不到BPDU认为链路故障

整网收敛时间约 50秒

十、STP 拓扑变更机制

  1. 链路故障，交换机发 TCN 报文 向上传至根桥
  2. 根桥下发 TC 标记，全网缩短MAC地址老化时间，快速刷新表项
  3. 否则要等MAC默认老化300秒，业务长时间不通

十一、STP 常用配置命令

  1. 配置生成树模式
  1. 修改交换机优先级（4096倍数）
  1. 直接指定根桥/备根桥
  1. 修改路径开销标准
  1. 关闭STP

十二、易错必记考点

  1. STP 选路越小越优先；OSPF DR/BDR 是越大越优先
  2. 优先级必须是 4096 倍数：0、4096、8192……
  3. 根桥无根端口，非根桥有且只有一个根端口
  4. 阻塞端口只收BPDU，不转发业务数据
  5. 拓扑变化靠TCN报文刷新MAC表，不然业务长时间断流
  6. 链路带宽越大，路径开销越小，越容易被选成转发端口

vlan间路由

发表于 2026-05-15

一、VLAN间路由基础原理

  1. 每个VLAN都是独立广播域、独立子网，二层天然隔离，不同VLAN主机不能直接二层互通。
  2. 普通二层交换机无法跨VLAN转发，必须依靠路由技术才能实现VLAN间通信。
  3. 路由器不能识别二层VLAN标签，需要特殊配置才能处理带Tag的数据帧。
  4. 实现VLAN间路由两种主流方式：
    • 路由器+二层交换机（物理多接口、单臂路由）
    • 三层交换机（VLANIF 虚接口路由）

二、VLAN间通信三种实现方式

1. 多物理接口路由（老式方式）

  • 每个VLAN单独用一条物理链路连接路由器一个物理接口
  • 缺点：浪费路由器接口，VLAN多了不够用，基本不实用

2. 单臂路由（子接口路由）

  • 交换机与路由器互联链路配置为 Trunk，允许多个VLAN带标签通过。
  • 路由器一个物理接口划分多个子接口，一个子接口对应一个VLAN。
  • 子接口终结802.1Q标签，充当对应VLAN的网关。
  • 子接口数量 = 业务VLAN数量；VLAN总范围0~4095（4096个，2的12次方）。

3. 三层交换机 MLS 路由

  • 三层交换机自带路由功能，无需外接路由器。
  • 通过创建 VLANIF 虚拟接口 作为各VLAN网关，实现三层互通。
  • 转发效率远高于单臂路由，企业网主流方案。

三、单臂路由核心配置与命令

  1. 子接口绑定VLAN、终结标签
  1. 开启子接口ARP广播（默认关闭，必须配置否则无法正常通信）
  1. 子接口配置IP地址，作为该VLAN网关

重点：子接口必须绑定对应VLAN才能正常转发流量。

四、三层交换机关键知识点 & 命令

  1. 创建VLAN虚拟接口，做网关

要求：VLANIF编号必须和已存在的VLAN编号一致。

  1. 接口二层/三层模式切换
  • 设为二层接口：portswitch
  • 设为三层接口：undo portswitch
  1. 原理理解
    三层交换机 = 二层交换 + 内置路由功能，内部可直接完成VLAN间三层转发，不用外接路由器。

五、核心必记考点

  1. 不同VLAN二层隔离，必须三层路由才能互通。
  2. 路由器不认VLAN标签，靠子接口dot1q终结解析标签。
  3. 单臂路由：一条物理链路、多个子接口、一个子接口对应一个VLAN网关。
  4. 子接口默认无ARP广播，必须手动开启 arp broadcast enable。
  5. 三层交换机用 VLANIF 虚接口 实现VLAN间路由，是现网主流。
  6. VLAN总数最大 4096 个，由12位二进制决定。

二层vlan技术

发表于 2026-05-15

一、VLAN 产生背景

  1. 交换机默认所有接口都在 VLAN1，同属一个广播域。
  2. 没划分VLAN前，所有主机同一广播域，容易产生广播风暴。
  3. 无法按业务灵活隔离广播域，网络规模变大后严重影响性能。
  4. 划分VLAN可以逻辑划分广播域，不用改动物理布线。

二、VLAN 核心作用与优点

作用

  • 把一个物理交换机，逻辑划分成多个虚拟局域网
  • 隔离广播域：不同VLAN二层不能直接通信，ARP无法跨VLAN传递
  • 跨VLAN通信必须借助路由器/三层设备

四大优点

  1. 限制广播域范围，抑制广播风暴
  2. 提升局域网安全性，不同VLAN二层隔离
  3. 灵活组建虚拟工作组，不受物理位置限制
  4. 简化网络运维与管理

重要区分

划分VLAN常把每个VLAN对应一个独立子网，但VLAN ≠ 子网，只是人为搭配使用。

三、802.1Q 协议与帧格式

  1. IEEE 802.1Q 是VLAN官方标准
  2. 在以太网帧源MAC和协议类型之间插入 4字节Tag标签
  3. 两种帧类型：
    • Untagged无标记帧：原始普通帧，PC终端发出都是无标签帧
    • Tagged有标记帧：携带802.1Q标签、带VLAN ID，交换机之间转发使用

四、VLAN 三种链路/端口类型

1. Access 接入端口

  • 用于交换机 ↔ 主机PC
  • 链路只传 Untagged 帧
  • 收：PC发无标签帧，交换机按接口PVID打上VLAN标签
  • 发：往外发数据前剥离标签，发给PC（PC不能识别标签）

2. Trunk 干道端口

  • 用于交换机↔交换机、交换机↔路由器
  • 允许多个VLAN通过，默认传 Tagged 帧
  • 收：有标签直接保留；无标签打上端口PVID
  • 发：同PVID剥离标签，不同PVID带标签转发

3. Hybrid 混杂端口

  • ENSP/华为交换机接口默认类型就是 Hybrid
  • 既能连主机、也能连交换机，兼容Access和Trunk功能
  • 可手动配置哪些VLAN带标签、哪些剥离标签，灵活性最高

五、PVID 端口默认VLAN

  1. PVID = Port VLAN ID 端口缺省VLAN
  2. 华为交换机所有接口默认PVID=1
  3. 作用：端口收到无标签帧时，自动打上该端口PVID对应的VLAN标签

六、三种端口核心转发规则

Access

  • 入：无标签 → 打PVID标签
  • 出：同VLAN → 剥标签发给终端

Trunk

  • 入：有标签保留；无标签打PVID
  • 出：VLAN和PVID相同剥标签，不同则带标签转发

通用口诀

入帧：有标留标，无标打PVID
出帧：同PVID剥标，异PVID带标

七、报文处理流程

交换机收到以太网帧：

  1. 判断是否带Tag
  2. 无Tag → 打上接口PVID
  3. 检查交换机是否存在该VLAN，不存在直接丢弃
  4. 检查出接口是否允许该VLAN通过
  5. 允许则按端口类型做标签保留/剥离后转发

八、基础配置要点

  1. 华为/ENSP 交换机接口默认端口类型：Hybrid
  2. 修改端口类型命令：port link-type access/trunk/hybrid
  3. 可单独修改接口 PVID，控制默认所属VLAN

九、核心必记知识点

  1. VLAN 隔离二层广播域，不同VLAN默认无法二层互通
  2. PC 只能收发无标签帧，标签由交换机内部添加和剥离
  3. Access 接终端、Trunk 接交换机、Hybrid 万能兼容
  4. 同广播域 = 同VLAN，不同VLAN必须三层路由才能通信
  5. 所有端口默认 PVID=1，默认都在 VLAN1 同一广播域

ospf协议

发表于 2026-05-15

一、OSPF 基础简介

OSPF 全称：Open Shortest Path First 开放式最短路径优先协议

  1. 属于 链路状态型 IGP 内部网关路由协议
  2. 用来替代 RIP：解决 RIP 收敛慢、易环路、扩展性差的问题
  3. 协议封装：IP 协议号 89
  4. 更新特点：触发式增量更新，只发送拓扑变化部分，不整表刷新
  5. 度量值参考：以带宽为依据计算开销 Cost

补充常见协议号：

  • ICMP：1
  • TCP：6
  • UDP：17
  • OSPF：89

二、OSPF 区域 Area 核心概念

1. 区域作用

  • 适配大型网络，在 AS 内划分多个区域
  • 减少路由表条目，降低路由器 CPU、内存消耗
  • 网络拓扑变化仅影响本区域，提升网络稳定性

2. 区域划分规则

  • 以接口为单位划分，不是以路由器为单位
  • 不能说“路由器属于某个区域”，只能说“路由器某个接口属于某区域”
  • 同区域路由器仅维护本区域完整链路状态信息

3. 区域类型

  1. 骨干区域 Area 0
    • 核心区域，负责转发非骨干区域间路由
    • 所有非骨干区域必须直连 Area 0
  2. 非骨干区域（常规区域）
    • 非 Area 0 都属于此类
    • 非骨干区域之间交换路由，必须经过骨干区域中转

三、OSPF 路由器角色分类

  1. 内部路由器 IR：所有接口都在同一个区域
  2. 骨干路由器：至少有一个接口在 Area 0
  3. ABR 区域边界路由器：同时连接骨干区域和非骨干区域
  4. ASBR 自治系统边界路由器：引入外部路由（静态、其他协议路由）
    • ASBR 不一定是 ABR
    • 可存在于任意区域，只要引入外部路由即为 ASBR

四、OSPF 核心工作流程

  1. 发送 Hello 包，发现并建立邻居
  2. 传播 LSA 链路状态通告（链路=接口，状态=地址/掩码/开销/邻居关系等）
  3. LSA 在整个区域内泛洪，不只是直连邻居
  4. 收集所有 LSA，生成 LSDB 链路状态数据库（同区域所有路由器 LSDB 完全一致）
  5. 运行 SPF 最短路径算法，计算最优路由，存入路由表

五、OSPF 三张核心表

  1. 邻居表：记录所有 OSPF 邻居关系
  2. LSDB 链路状态数据库：整个区域拓扑底图，同区域完全同步
  3. 路由表：只存放算法算出的最佳路由

命令查看邻居表：display ospf peer

重点：

  • 邻居≠一定邻接，邻接一定是邻居
  • 同区域：邻居表、路由表可以不同，但 LSDB 必须完全相同

六、Router-ID 路由器标识

作用

唯一标识一台 OSPF 路由器，运行 OSPF 必须有 RID

RID 选举顺序（从上到下优先）

  1. 手动配置（推荐）
  2. 选取活动环回接口最大 IP
  3. 选取活动物理接口最大 IP
  4. 无任何配置默认 RID：0.0.0.0

特性

  • 非抢占性：选好后不会自动变更，需重启 OSPF 进程才会重新选举
  • 手动配置命令：ospf 1 router-id x.x.x.x
  • RID 格式同 IP，和路由器接口实际地址无关

七、OSPF 5 种报文类型

类型 报文名称 核心作用
1 Hello 建立、发现、维持邻居关系
2 DD 数据库描述 发送 LSDB 摘要，仅 LSA 头部
3 LSR 链路状态请求 向邻居请求缺失的 LSA 详细信息
4 LSU 链路状态更新 携带完整 LSA 发送路由更新
5 LSAck 链路状态确认 确认收到 LSU 报文

补充：

  • LSA 不是独立数据包，封装在 LSU 里传输
  • 网络拓扑变化时触发发送 LSU，对方回复 LSAck 确认

八、OSPF 邻居状态机

状态依次：
Down → Init → 2-Way → ExStart → Exchange → Loading → Full

状态详解

  • Down：未收到 Hello 包，失效状态
  • Init：收到 Hello，但报文里无自己 RID
  • 2-Way 双向稳定状态：收到 Hello 且发现自身 RID，建立邻居
  • ExStart：协商主从关系，RID 大的为 Master
  • Exchange：交互 DD 报文，同步 LSDB 摘要
  • Loading：交互 LSR/LSU，请求并下发完整 LSA
  • Full 完全邻接稳定状态：LSDB 完全同步

只有 2-Way、Full 是稳定状态

九、OSPF 邻居建立必备条件

  1. 三层直连
  2. Router-ID 唯一
  3. Hello/Dead 间隔时间一致
  4. 区域 ID 一致
  5. 认证配置一致（启用认证时）
  6. 链路 MTU 一致（思科默认检查，华为默认不检查）
  7. 以太网环境：网络地址、子网掩码一致
  8. 末梢区域特殊配置一致

补充：

  • 必须同一区域才能建邻居
  • 点到点非以太网：掩码不同也可建立邻居

十、OSPF 网络类型（基于接口）

  1. 广播型 BMA：以太网默认类型
  2. 点到点：PPP、HDLC 链路默认
  3. NBMA 非广播多路访问：帧中继、ATM 默认
  4. 点到多点 等其他类型

DR/BDR 只在多路访问网络（BMA、NBMA）选举，跟接入设备数量无关，只要是以太网接口就属于多路访问

十一、DR 与 BDR 详解

作用

多路访问网络中减少邻接关系数量，节省带宽、降低设备性能消耗

角色划分

  • DR 指定路由器：负责收集、转发全网 LSA
  • BDR 备用指定路由器：DR 故障时立即接管
  • DRothers 普通路由器

邻接关系规则

  • DR、BDR 与所有 DRothers 保持 Full 邻接
  • DRothers 之间只维持 2-Way 邻居，不建立 Full

组播地址

  • 224.0.0.5：所有 OSPF 路由器监听
  • 224.0.0.6：DR/BDR 专用，DRothers 向此地址发更新

选举规则

  1. 接口优先级 0~255，默认 1，优先级越高越优先
  2. 优先级为 0 不参与选举
  3. 优先级相同，RID 越大越优先
  4. 先选 BDR，再升为 DR

核心特性

非抢占性：选举完成后，新接入更高优先级设备，不会抢占现有 DR/BDR 角色；仅 DR/BDR 全部故障或重启 OSPF 才会重新选举

十二、OSPF 度量值 Cost 开销

  1. 计算公式：
    [
    Cost = \frac{10^8}{接口带宽(bps)}
    ]
    参考带宽默认 100Mbps

  2. 路由总开销：从源到目标所有出站接口 Cost 累加

  3. 每个运行 OSPF 的接口都独立维护自身 Cost 值

十三、重点易错总结

  1. RIP 距离矢量、OSPF 链路状态，OSPF 无路由环路、收敛更快
  2. 区域边界在接口，不在路由器
  3. ASBR 和 ABR 概念独立，ASBR 不一定是 ABR
  4. 同区域 LSDB 必须一致，邻居表、路由表可以不同
  5. 邻居不一定邻接，邻接一定是邻居
  6. DR/BDR 选举非抢占，优先级 0 无参选资格
  7. OSPF 基于带宽算开销，不是跳数
  8. 224.0.0.5 全网、224.0.0.6 仅 DR/BDR
  9. RID 手动配置最优，选举后非抢占

rip协议

发表于 2026-05-14 更新于 2026-05-15

一、RIP 基础概述

RIP 全称 Routing Information Protocol 路由信息协议

  1. 协议类型：距离矢量路由协议，属于 IGP 内部网关协议
  2. 适用场景：中小型网络，分为 RIPv1、RIPv2 两个版本
  3. 传输承载：基于 UDP 协议，默认目标端口号 520
  4. 更新机制：周期性路由更新
  5. 防环特性：支持水平分割、毒性逆转、触发更新
  6. 层级归属：传输层之上，归为应用层协议

二、RIP 核心特点

  • 配置简单、易于维护
  • 适配小型局域网 / 中小型网络
  • 度量值采用跳数计算路由远近
  • 仅接口开启 RIP 后，才会收发路由更新报文

三、RIP 度量值规则

  1. 以跳数作为唯一度量值，衡量到达目标网络距离
  2. 直连网络默认跳数为 0
  3. 路由器发送路由更新时，度量值自动 +1
  4. 最大有效跳数：15 跳
  5. 16 跳 判定为网络不可达

四、RIP 周期性更新机制

  1. 网络稳定后，路由器默认 30s 周期性发送完整路由表更新
  2. 时间并非严格精准 30 秒，存在随机偏移
  3. 仅宣告网段内的接口，参与 RIP 路由收发

五、RIPv1 与 RIPv2 核心区别

表格

对比项 RIPv1 RIPv2
协议类型 有类别路由协议 无类别路由协议
VLSM/CIDR 不支持 支持 VLSM、路由聚合、CIDR
报文发送方式 仅广播 255.255.255.255 广播 / 组播 224.0.0.9
认证功能 不支持密码认证 支持明文认证、MD5 密文认证

配置切换命令：version 2 可将 RIPv1 升级为 RIPv2

六、RIP 报文格式要点

RIPv1 报文

  • UDP 端口固定 520
  • 目的地址：广播地址 255.255.255.255
  • 报文存在多个 Must be Zero 保留字段
  • 无子网掩码、下一跳、路由 Tag 字段

RIPv2 报文

  • 同样使用 UDP 520 端口
  • 默认组播地址：224.0.0.9
  • 新增字段：路由标签、子网掩码、下一跳
  • 支持认证字段，可配置明文 / MD5 认证

七、RIP 路由环路产生原因

路由环路

16 跳

八、RIP 三大环路避免机制

1. 水平分割

从某个接口学到的路由，不会从该接口再发回邻居

默认开启

2. 毒性逆转

16（不可达）

默认关闭

水平分割 + 毒性逆转同时开启时，以毒性逆转为准

3. 触发更新

发生故障 / 变更时

九、RIP 关键配置命令大全

表格

十、重点易错知识点总结

  1. 度量值修改是跳数累加加减，不是直接覆盖修改为固定值
