rip协议

发表于 2026-05-14 更新于 2026-05-15

一、RIP 基础概述

RIP 全称 Routing Information Protocol 路由信息协议

  1. 协议类型：距离矢量路由协议，属于 IGP 内部网关协议
  2. 适用场景：中小型网络，分为 RIPv1、RIPv2 两个版本
  3. 传输承载：基于 UDP 协议，默认目标端口号 520
  4. 更新机制：周期性路由更新
  5. 防环特性：支持水平分割、毒性逆转、触发更新
  6. 层级归属：传输层之上，归为应用层协议

二、RIP 核心特点

  • 配置简单、易于维护
  • 适配小型局域网 / 中小型网络
  • 度量值采用跳数计算路由远近
  • 仅接口开启 RIP 后，才会收发路由更新报文

三、RIP 度量值规则

  1. 以跳数作为唯一度量值，衡量到达目标网络距离
  2. 直连网络默认跳数为 0
  3. 路由器发送路由更新时，度量值自动 +1
  4. 最大有效跳数：15 跳
  5. 16 跳 判定为网络不可达

四、RIP 周期性更新机制

  1. 网络稳定后，路由器默认 30s 周期性发送完整路由表更新
  2. 时间并非严格精准 30 秒，存在随机偏移
  3. 仅宣告网段内的接口，参与 RIP 路由收发

五、RIPv1 与 RIPv2 核心区别

表格

对比项 RIPv1 RIPv2
协议类型 有类别路由协议 无类别路由协议
VLSM/CIDR 不支持 支持 VLSM、路由聚合、CIDR
报文发送方式 仅广播 255.255.255.255 广播 / 组播 224.0.0.9
认证功能 不支持密码认证 支持明文认证、MD5 密文认证

配置切换命令：version 2 可将 RIPv1 升级为 RIPv2

六、RIP 报文格式要点

RIPv1 报文

  • UDP 端口固定 520
  • 目的地址：广播地址 255.255.255.255
  • 报文存在多个 Must be Zero 保留字段
  • 无子网掩码、下一跳、路由 Tag 字段

RIPv2 报文

  • 同样使用 UDP 520 端口
  • 默认组播地址：224.0.0.9
  • 新增字段：路由标签、子网掩码、下一跳
  • 支持认证字段，可配置明文 / MD5 认证

七、RIP 路由环路产生原因

路由环路

16 跳

八、RIP 三大环路避免机制

1. 水平分割

从某个接口学到的路由，不会从该接口再发回邻居

默认开启

2. 毒性逆转

16（不可达）

默认关闭

水平分割 + 毒性逆转同时开启时，以毒性逆转为准

3. 触发更新

发生故障 / 变更时

十、重点易错知识点总结

  1. 度量值修改是跳数累加加减，不是直接覆盖修改为固定值
  2. undo rip input/output 可单独开启 / 关闭，不发 ≠ 不收
  3. 被动接口只收不发，但仍能学习其他路由器路由
  4. RIPv1 无认证，RIPv2 支持明文、MD5 两种认证
  5. 15 跳可达、16 跳直接判定不可达，是 RIP 核心规则
  6. 水平分割与毒性逆转共存，毒性逆转优先级更高

一、路由基础概念

1. 路由过程

路由是双向的，通信必须有去有回；路由器转发数据包必须明确目的网络、下一跳、出接口。

  • 下一跳：另一台路由器的接口IP地址，可存在多个下一跳。
  • 出接口：数据包从本路由器转发出去的接口。

2. 路由器核心工作

  • 接收数据包，解析IP头部目的IP地址
  • 在路由表中查找、匹配最佳路径
  • 维护、更新路由表
  • 路由表中不存在目标网络的数据包，直接丢弃

一、应用层通信模型

应用协议定义终端设备间的应用通信规则；通信模型体现应用协议宏观通信规则，主要分为两类：

  1. C/S（客户端-服务器）模型
  2. P2P（点对点）模型

P2P模型特点

  • 设备无明显角色特征
  • 设备之间建立对等连接，实现对等通信
  • 设备既可提供服务，也可请求服务

二、基于TCP协议的远程访问应用层协议

1. Telnet协议

  • 通信模型：C/S
  • 传输层协议：TCP
  • 端口号：23
  • 数据形式：明文
  • 角色定义：客户端为管理设备，服务器为被管理设备

2. SSH协议（Telnet改进版）

  • 提供服务器认证，客户端可识别服务器身份
  • 用户认证支持密码认证、公钥认证两种方式
  • 用户认证信息以密文传输或不传输
  • 用户业务数据全程密文传输

三、基于UDP的应用层协议

DHCP协议

  • 作用：为特定网络内设备分配IP地址、DNS等信息
  • 通信模型：C/S
  • 传输层协议：UDP
  • 端口号：67、68
  • 数据形式：明文

四、同时基于TCP和UDP的应用层协议

DNS协议

1. 核心作用

实现计算机名称与IP地址双向解析。

2. 基础参数

  • 通信模型：C/S
  • 传输层协议：TCP/UDP
  • 端口号：53
  • 数据形式：明文

3. 域名产生原因

网络计算机可通过IP地址唯一标识，但IP地址不易记忆，且无法永久绑定设备；域名由点分隔字符组成，可建立域名与IP地址映射关系，访问域名等同于访问IP地址。

4. 早期非等级域名空间缺陷

  • 字符域名易产生命名冲突
  • 域名空间集中管理，设备增多加重管理负担
  • 域名与IP映射常变动，维护工作量大

5. 域名层级划分

顶级域分组织模式、地理模式：

模式 示例 说明
组织模式 com、edu、gov、mil、net、int、org 商业组织、教育机构、政府机构等
地理模式 cn（中国）、us（美国） 按国家划分

6. 域名解析查询方式

  • 递归查询：本地DNS服务器无记录时，由该服务器代为查询其他DNS服务器，直至获取结果返回客户端。
  • 迭代查询：本地DNS服务器无记录，仅告知客户端下一级服务器地址，由客户端自行继续查询。

7. 域名解析分类

  • 静态域名解析：手动配置域名与IP映射表，如Windows系统hosts文件。
  • 动态域名解析：通过域名解析器，依靠DNS客户端与服务器报文交互完成解析。

8. DNS完整查询流程

DNS客户端 → 本地域名服务器 → 根域名服务器 → .com顶级域名服务器 → huawei.com域名服务器 → 返回对应IP地址

ARP协议全解析：从原理到实战

发表于 2026-05-14

一、什么是 ARP 协议

ARP（Address Resolution Protocol，地址解析协议） 是一个位于 TCP/IP 协议栈底层的核心协议，负责将网络层的 IP 地址 解析成数据链路层的 MAC 地址。

为什么需要 ARP？因为在实际通信中，IP 数据报最终需要封装成帧才能通过物理网络发送，而以太网设备只认识 48 位的 MAC 地址，不认识 32 位的 IP 地址——ARP 就是这两个世界之间的“翻译官”。

ARP 仅用于 IPv4，IPv6 使用邻居发现协议（NDP）来完成类似的功能。

二、ARP 工作原理

ARP 的核心流程可以概括为 广播请求、单播响应。

1. 同广播域下的完整过程

第 1 步：查 ARP 缓存

主机 A 要向主机 B 发送数据时，会先检查自己的 ARP 缓存表。如果缓存中有 B 的 IP 与 MAC 映射，就直接使用，无需再次解析。

第 2 步：发送 ARP 广播请求

如果缓存中没有对应记录，主机 A 向本地网络广播一个 ARP 请求包，内容大概是：“谁是 192.168.1.2？请告诉我你的 MAC 地址”。该请求包含发送方的 IP/MAC 和目标 IP 地址。

第 3 步：目标主机单播响应

网络中的所有设备都会收到这个请求，但只有 IP 地址匹配的目标主机会响应。它向主机 A 单播回复一个 ARP 响应包，内容为：“我是 192.168.1.2，我的 MAC 地址是 00:11:22:33:44:55”。

第 4 步：更新 ARP 缓存

主机 A 收到响应后，将主机 B 的 IP 与 MAC 映射存入 ARP 缓存。下次再与 B 通信时，直接查缓存就行，不用再发广播了。

2. 不同广播域下的通信

如果目标主机在另一个子网，ARP 广播无法跨网段传输。这时源主机会先查路由表，找到默认网关，然后通过 ARP 获取网关的 MAC 地址，把数据交给网关，由网关负责三层路由转发到目标子网。

三、ARP 报文格式

ARP 报文总长度为 28 字节，封装在以太网帧中，帧类型字段为 0x0806。

主要字段含义如下：

字段 长度 说明
硬件类型 2 字节 硬件接口类型，以太网值为 1
协议类型 2 字节 要映射的协议地址类型，IP 为 0x0800
硬件地址长度 1 字节 MAC 地址长度，以太网为 6
协议地址长度 1 字节 IP 地址长度，IPv4 为 4
操作类型 2 字节 1=ARP 请求，2=ARP 响应，3=RARP 请求，4=RARP 响应
发送方 MAC 6 字节 源设备的 MAC 地址
发送方 IP 4 字节 源设备的 IP 地址
目标 MAC 6 字节 请求时填 0，响应时填目标 MAC
目标 IP 4 字节 目标设备的 IP 地址

ARP 请求包与响应包的区别：请求包的操作类型为 1，目标 MAC 字段为全 0；响应包的操作类型为 2，目标 MAC 字段填充实际的硬件地址。

四、ARP 缓存

为了减少频繁的广播请求，每台主机和路由器都会维护一张 ARP 缓存表，记录 IP 与 MAC 的映射关系。

缓存表项的核心内容： IP 地址、对应的 MAC 地址、生存时间（TTL） 及状态标识（如 FREE、PENDING、RESOLVED）。

动态条目与老化机制： 动态条目有生命周期，过期后自动删除。Windows 系统中动态条目默认 2 分钟失效，Cisco 路由器默认 240 分钟。到期前会有探测机制（例如发 ARP 探测报文），若仍未收到回应，条目被删除。

五、ARP 相关协议

1. 代理 ARP

代理 ARP 是一种技术，允许路由器代替远程目标响应 ARP 请求。当不同子网的主机需要通信而源主机未配置默认网关时，路由器收到 ARP 请求后发现目标 IP 在其他子网，会用自己的 MAC 地址代为响应，从而建立通信链路。但现代网络通常依赖默认网关而非代理 ARP 来实现跨网通信。

2. 免费 ARP（GARP）

GARP 是一种特殊的 ARP 请求，发送方用自己的 IP 地址作为目标 IP，主动通知网络中其他设备更新 ARP 缓存。主要用途：

  • 检测 IP 地址冲突：发送 GARP 后若收到响应，说明存在 IP 冲突。
  • 更新网络设备缓存：当设备 IP 或 MAC 变化（如主备切换、VRRP 故障倒换）时，通过 GARP 通知其他设备更新映射关系，避免连接中断。

3. 逆地址解析协议（RARP）

RARP 是 ARP 的逆向过程，根据 MAC 地址获取 IP 地址，主要用于无盘工作站。这类设备启动时没有本地磁盘存储 IP 配置，只能从网卡读取 MAC 地址，然后广播 RARP 请求到网络上的 RARP 服务器，由服务器响应分配 IP 地址。如今 RARP 已被更完善的 DHCP 协议取代。

六、ARP 攻击与防御

ARP 协议设计时假设网络内所有主机互相信任，没有任何验证机制——这本身就是最大的安全隐患。

1. ARP 攻击类型

ARP 欺骗（ARP Spoofing）/ARP 投毒（ARP Poisoning）： 攻击者发送伪造的 ARP 响应，诱骗受害者更新 ARP 缓存，将合法 IP（如网关 IP）映射到攻击者的 MAC 地址。攻击通常双向进行：

  • 欺骗受害者，让受害者认为攻击者的 MAC = 网关 IP
  • 欺骗网关，让网关认为攻击者的 MAC = 受害者 IP

于是，受害者与网关之间的所有流量都流经攻击者——经典的 中间人攻击（MITM）。攻击者可监听、篡改或拦截通信数据。

ARP 泛洪攻击： 攻击者发送大量伪造 ARP 报文，消耗目标设备资源，属于 DoS（拒绝服务）攻击的一种。

2. 常见防御方法

  • 静态 ARP 绑定：手动添加 IP 与 MAC 的静态映射，防止动态学习被篡改。
  • ARP 防火墙：部署专用防护软件，自动监测与阻止可疑 ARP 报文。
  • 使用 VPN：VPN 加密通信流量，即使被 ARP 欺骗也无法窃取有效信息。
  • DAI（动态 ARP 检测）：交换机层面验证 ARP 报文合法性（企业级网络常用）。

七、常用 ARP 命令

命令 作用
arp -a 查看本机 ARP 缓存中的所有条目
arp -d [IP] 删除指定 IP 的 ARP 缓存条目
arp -s <IP> <MAC> 添加静态 ARP 条目（不会因老化而自动删除）
ip neigh show Linux 中使用 iproute2 工具包查看邻居缓存（推荐，功能更强大）
ip neigh flush all Linux 中清空所有邻居缓存条目

八、必背核心总结

  1. ARP 的核心作用：32 位 IP 地址 ↔ 48 位 MAC 地址的动态映射，数据链路层封装的关键。
  2. 工作模式：广播请求，单播响应——请求发向全网，目标主机单独回复。
  3. ARP 缓存：减少广播次数，提升通信效率；动态条目有老化时间，超时后自动删除。
  4. 代理 ARP：路由器代答不同子网的 ARP 请求，用自身 MAC 响应，实现跨网通信。
  5. 免费 ARP（GARP）：主动通告 IP/MAC 映射变化，用于 IP 冲突检测和故障倒换通知。
  6. RARP：MAC 地址 → IP 地址，主要用于无盘工作站启动时获取 IP。
  7. ARP 攻击的本质：ARP 协议无身份验证机制→攻击者发送伪造 ARP 报文→篡改受害主机的 ARP 缓存→实现中间人攻击。
  8. 防御要点：静态 ARP 绑定、ARP 防火墙、加密通信（VPN）、设备层动态检测。

九、常见面试题

1. ARP 协议的作用是什么？

实现 32 位 IP 地址到 48 位 MAC 地址的转换。广播询问，单播答复。

2. 为什么引入 ARP 缓存？

将 IP 与 MAC 的映射关系保存在缓存中，避免每次通信都运行 ARP 解析，减少广播流量，提升通信效率。

3. ARP 缓存中毒的攻击原理是什么？

攻击者向目标主机发送伪造的 ARP 响应包（以网关身份），诱骗目标更新 ARP 缓存，使发往网关的流量重定向至攻击者，实现监听、篡改。

4. 如何防御 ARP 欺骗？

静态 ARP 绑定、部署 ARP 防火墙、启用 DAI 检测、使用 VPN 加密等。

5. 代理 ARP 的应用场景是什么？

当通信双方位于不同物理子网且源主机未配置默认网关时，路由器代答 ARP 请求，使两台主机“认为”自己属于同一广播域，从而建立通信链路。

6. 免费 ARP 的两个主要作用是什么？

检测 IP 地址冲突；主动通知网络中其他设备更新 ARP 缓存（常见于 VRRP/HSRP 主备切换等场景）。

传输层核心知识点详解（端口号 + TCP 可靠机制）

发表于 2026-05-14

一、端口号：应用进程的专属门牌号

端口号是 16 位无符号整数，占用 2 字节，取值范围：0～65535，共 65536 个。

1. 核心作用

  • 区分同一设备上不同应用服务（如 HTTP=80、HTTPS=443、SSH=22）
  • 标识绑定应用层协议，端口对应具体服务进程
  • 支持自定义修改，不强制固定端口

2. 端口号三大分类

分类 范围 说明
知名端口 0–1023 IANA 统一分配，固定用于标准网络服务
注册端口 1024–49151 可供厂商、用户自行注册使用
动态/私有端口 49152–65535 操作系统临时分配给客户端进程，通信结束自动释放

通俗理解：IP 地址找到目标主机，端口号找到主机上具体的应用程序。

二、TCP 协议可靠传输核心机制

TCP 是面向连接、可靠交付的传输层协议，依靠序列号、确认号、标志位、滑动窗口、超时重传等机制保证数据不丢、不乱、不重复。

1. 序列号 Seq 与确认号 Ack

  • 序列号 Seq：标记当前报文段数据第一个字节在整个字节流中的位置。
  • 确认号 Ack：接收方告知发送方，已收到前面所有数据，下次期望接收的起始序号。
  • 示例：Seq=1，携带 9 字节数据，接收方回复 Ack=10。
  • 重要：除第一次 SYN 建连报文外，其余所有 TCP 报文都必须携带有效 Ack 确认。

2. TCP 六大标志位

标志位 含义 作用
SYN 同步位 用于三次握手建立连接，协商初始序列号
ACK 确认位 Ack 字段生效时必须置 1
FIN 终止位 用于四次挥手释放连接
RST 重置连接 强制断开异常连接
PSH 推送位 立即向上层递交数据，不缓存
URG 紧急位 标识紧急数据优先处理

3. 可靠性保障核心逻辑

  • 累计确认：一次 ACK 可以确认多段按序到达的数据，提升传输效率。
  • 超时重传：发送方超时未收到确认，自动重传丢失报文。
  • 滑动窗口 & 流量控制：接收方通过窗口大小告知发送方自己的接收能力，限制发送速率，防止拥塞和数据溢出。
  • 连接优雅断开：四次挥手双向独立关闭，保证双方剩余数据全部传输完毕再断开。

三、TCP 与 UDP 核心区别

特性 TCP（传输控制协议） UDP（用户数据报协议）
连接方式 面向连接 无连接
传输可靠性 可靠传输，无丢失无乱序 尽力而为传输，不保证可靠
控制机制 支持流量控制、窗口机制、重传机制 无流量控制、无窗口机制
典型应用 HTTP、FTP、HTTPS DNS、TFTP、流媒体

四、结语

传输层是互联网稳定通信的基石。弄懂端口号作用、TCP 序号确认、标志位、可靠传输机制，不仅能应付考试预习，也能看懂抓包分析、理解网页加载、即时通讯为什么稳定不丢消息。

ip地址基础

发表于 2026-05-13

一、什么是 IP 地址

IP 全称 IP Address，是网络里每一台通信设备的唯一身份标识。

IPv4 采用 32 位二进制 组成，日常用点分十进制表示
示例：192.168.1.1/24

IP 地址固定分成两部分：

  • 网络位：代表属于哪一个网段
  • 主机位：代表网段里的某一台具体设备

网络位和主机位的分界线，由子网掩码决定。

二进制换算举例：
192.168.5.1 二进制：
11000000.10101000.00000101.01111011
十进制计算：128+64=192，就是这么换算来的。

二、子网掩码核心知识点

子网掩码英文：Subnet Mask

1. 作用

区分 IP 地址里哪部分是网络位、哪部分是主机位。

2. 编码规则

二进制里：

  • 1 = 网络位
  • 0 = 主机位
    且 1 和 0 必须连续，不能打乱穿插。

3. 有效主机数量计算公式

可用主机地址数 = 2^{主机位数} - 2

为什么要减 2？
要扣除网络地址和广播地址，这两个地址不能分给电脑、手机等终端使用。

三、IP 地址 A/B/C 类分类详解

1. 地址范围划分

  • A 类地址：首段 1～127
  • B 类地址：首段 128～191
  • C 类地址：首段 192～223

2. 默认掩码与网段数量

  • A 类：默认大网段，整体一个大网络
  • B 类：默认掩码 /16，包含 16 个标准网段
  • C 类：默认掩码 /24，网段范围 xx.xx.0 ~ xx.xx.255，一共 256 个网段

3. 特殊地址：127 环回地址

  • 127.x.x.x 属于环回虚拟接口
  • 没有网卡也能 ping 通
  • 用途：专门测试本地 TCP/IP 协议栈是否正常工作

4. 私网 & 公网 & IPv6

  • 家里、公司内网用的都是私网地址
  • 访问互联网时，私网地址会转换成公网地址上网
  • IPv6 升级为 128 位，彻底解决 IP 地址不够用问题

四、为什么要做子网划分

传统 A/B/C 类大网段有很大弊端：

  • IP 地址资源严重浪费
  • 一个广播域设备太多
  • 广播报文泛滥，占用大量带宽

所以引入子网划分：向主机位借位，把一个大网段拆成多个小网段，分给不同部门使用。

五、子网划分核心原理

  • 从原本的主机位借出若干位，当做新的子网网络位
  • 借 n 位：可划分出子网数量 = 2^{n}
  • 剩余 m 位主机位：每个子网可用主机数 = 2^{m} - 2

六、经典子网划分实战案例

案例 1：C 类地址借 2 位划分

网段 192.168.1.0/24，借 2 位划分子网

  • 子网个数：2^{2} = 4 个
  • 剩余主机位 6 位
  • 每个子网有效主机：2^{6} - 2 = 62 个

案例 2：/28 子网划分实操

网段 61.179.150.0，掩码 /28

  • 网络位 28 位，剩余主机位 4 位
  • 块大小：2^{4} = 16
  • 就近取 16 倍数：32
  • 网络地址：61.179.150.32/28
  • 广播地址：61.179.150.47
  • 有效主机范围：33 ~ 46

案例 3：/26 网段地址范围

  • 142.68.1.64/26 → 可用主机：65～126
  • 142.168.102.128/26 → 可用主机：129～190
  • 192.168.102.192/26 → 可用主机：193～254

记住规则：子网第一个地址是网络地址，最后一个是广播地址，都不能分配给终端。

案例 4：大网段 /11 划分

网段 60.160.0.0/11

  • 第二段原有 8 位网络位，借出 3 位，剩 5 位
  • 块大小：2^{5} = 32
  • 网络地址：60.160.0.0
  • 下一个网段起始：160 + 32 = 192
  • 本网段广播地址：60.160.191.255

七、必背核心总结

  1. IPv4 32 位二进制，分网络位 + 主机位，子网掩码 1 看网络、0 看主机；
  2. 算主机地址一定要 减 2，剔除网络和广播地址；
  3. A/B/C 类默认掩码固定，大网段浪费严重，必须做子网划分；
  4. 子网划分口诀：借位划子网 → 算块大小 → 找网络地址 → 定广播范围；
  5. 127 环回地址测本地协议栈，内网用私网，上网转公网。
